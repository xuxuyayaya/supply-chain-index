# 产业链供应分析指数 · 产品需求文档

版本 V1.0｜日期 2026-11-18｜范围 Web 演示版

## 1. 产品定位

为产业链运营、研究与方案演示人员提供一个可复用的供应分析场景。用户应能回答三个问题。

1. 这条产业链的整体供应能力怎样？
2. 哪些指标和贸易结构解释了这一结果？
3. 某个关键部件由哪些层级供应，供货方向是什么？

网站沿用输入视频中「场景入口 → 案例详情 → 图表与关系下钻」的阅读顺序。正式接入既有门户时，可将本场景入口作为「产业链供应分析指数」卡片，链接至独立场景。当前交付独立网站。

## 2. 案例与适用范围

| 案例 | 地区和产业 | 角色 | 统计期 |
| --- | --- | --- | --- |
| 先进制造 | 海川示范区（虚构），工业机器人 | 默认通用案例，展示伺服驱动、精密减速器等关键部件 | 2026-10、2026-09 |
| 新能源装备 | 临汐示范区（虚构），储能装备 | 验证同一产品可适配另一类产业及部件 | 2026-10、2026-09 |
| 开封汽车及零部件 | 河南开封 | 参考案例，复现原交流材料的示例指数与贸易总额 | 2026-10 |

所有公开数据为演示数据。开封案例仅引用允许展示的示例数字，企业节点与供货边采用泛化名称和演示关系。地区、链类、统计期、指标、品类、节点和关系通过数据模型配置。首期提供只读浏览与分析，正式数据接入、编辑审批、登录、地图底图和导出预留后续版本。

## 3. 角色与主要流程

| 角色 | 任务 | 成功条件 |
| --- | --- | --- |
| 场景访客 | 选择适用案例和统计期，阅读指数与贸易结构 | 能看到当前案例、期次和演示性质，能打开计算说明 |
| 业务演示人员 | 从贸易品类进入供应追溯，解释关联路径 | 图表跳转后选中同一品类，点击节点能解释方向及关系状态 |
| 数据维护人员 | 用版本化数据增加或更正案例 | 无需复制网页即可通过同一接口和组件展示新案例，测试通过后发布 |

主流程为案例或期次选择 → 指数概览 → 指标口径 → 贸易结构 → 部件路径 → 企业详情。

## 4. 功能需求

| 编号 | 功能 | 界面与交互 | 异常行为 |
| --- | --- | --- | --- |
| F01 | 案例选择 | 默认先进制造、最近一期。切换案例时更新地区、期次、贸易及部件，重置旧节点和筛选 | 列表失败提供重试。单期案例显示禁用的期次选择器 |
| F02 | 指数卡片 | 展示总分、满分、案例、地区、期次、口径版本和演示标识。四项指标展示原值、权重、方向 | 任一指标无法计算时总分显示「暂不可计算」，有效指标继续展示 |
| F03 | 指标拆解 | 展示分子、分母、标准化得分、加权贡献和口径 | 数值为空使用缺值标识。有效零值正常显示 |
| F04 | 贸易结构 | 展示采购、销售、合计、品类购销排名、前五供应商采购额与占比、采购地金额；单位为亿元 | 当前品类没有对应路径时保留静态条目 |
| F05 | 品类联动 | 已映射品类按钮滚动到追溯区，并将焦点交给选中的部件筛选控件 | 地图关系未返回时展示就地重试 |
| F06 | 供应追溯 | 部件筛选、当前部件层级筛选、企业或地区关键词查询、重置、可见节点与关系计数 | 搜索无结果时显示范围提示 |
| F07 | 路径详情 | Tier 3 → Tier 2 → Tier 1 → 整机端；点击节点高亮可达上下游，详情列出直接关系、地区和来源；关联示意用虚线 | 路径采用业务层级图；窄屏支持横向滚动和键盘选择 |
| F08 | 数据通道 | GitHub Pages 优先读在线 API，超时切换至同源生成的演示快照，并提示当前通道 | 快照也无法获取时显示重试 |
| F09 | 并发请求 | 快速切换案例和部件时取消旧请求，最新选择决定渲染 | 取消请求不弹错误提示 |

## 5. 指标数据与计算

| 指标 | 分子 / 分母 | 方向 | 权重 | 开封演示原值 |
| --- | --- | --- | --- | --- |
| 环节覆盖率 | 已覆盖关键环节数 / 关键环节总数 | 正向 | 30% | 85% |
| 本地配套率 | 本地采购额 / 同范围采购总额 | 正向 | 30% | 82% |
| 供应商集中度 CR5 | 前五供应商采购额 / 同范围采购总额 | 逆向 | 20% | 28% |
| 龙头依赖度 | 链主营收 / 同范围链上营收 | 逆向 | 20% | 30% |

正向标准分为原值百分数，逆向标准分为 100 减去原值百分数。未舍入的标准分乘以权重再求和，最终显示到一位小数。开封复算为 25.5＋24.6＋14.4＋14.0＝78.5。分母缺失或不大于零、原值超界时指标记为缺失，不重分配权重。原方案还使用「各品类第一大供应商采购依存度」这一不同定义，本演示采用链主营收占比。接入正式数据前需确定统计版本、地区归属、样本、披露权限与阈值。

品类贸易额合计与总交易额勾稽。供应商排名分母为采购总额。海川和临汐的品类金额按期次总额和预设品类份额生成。采购地分类以示例数据提供的两类为准。追溯关系独立于指数计算。

## 6. 数据对象与 API

| 接口 | 输入与输出 |
| --- | --- |
| GET /api/health | 返回服务状态 |
| GET /api/cases | 返回案例标识、标题、地区、标签和期次 |
| GET /api/cases/{id}?period=YYYY-MM | 返回统计元数据、指数、评分明细、贸易汇总及部件映射 |
| GET /api/cases/{id}/trace?part={partId} | 返回部件、供应节点、有向关系及资料说明 |

无效案例、期次或部件返回 404。非 GET 请求返回 405。案例数据保存在版本控制的只读数据目录模块中，适合公开演示。公开接口仅出示演示汇总。正式扩展时可替换存储实现，保留案例、期次和资料版本的接口约定。

## 7. 架构与发布

- 前端使用 HTML、CSS 和 JavaScript，业务图采用 HTML 按钮、分层布局和 Canvas 连线。前端支持 GitHub Pages 的子目录路径。
- 后端使用 Node.js，负责从案例目录聚合指标、计算分数与返回追溯关系。本地后端同时服务前端，线上在 Render 运行。
- GitHub 存放前后端源码及 PRD。GitHub Pages 构建资产包含由同一后端数据模型生成的演示快照，作为 API 冷启动或网络异常期间的备用通道。
- 后端无写入、账号或数据库依赖。仅允许配置的 GitHub Pages 来源跨域读取。后续正式数据权限、数据审核和发布流程需独立设计。
